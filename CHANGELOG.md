# Changelog

## Unreleased

### Bug Fixes

- **[Data Types]** Fix `python_type_to_value_type` mapping `datetime64[ns]` and `datetime64[ns, tz]` pandas dtypes to `ValueType.INT64` instead of `ValueType.DATETIME`. When inferring feature types from a pandas DataFrame with datetime columns, the type name `"datetime64[ns]"` was looked up in the type map and incorrectly returned `INT64`. This caused datetime features to be recorded as integers in the feature store schema, losing temporal semantics and preventing proper datetime handling downstream. Fixed by mapping both `"datetime64[ns]"` and `"datetime64[ns, tz]"` to `ValueType.DATETIME`.

- **[Logger]** Fix `Logger._update_bound_vars_and_log` merging bound variables with wrong precedence, causing bound values to override per-call keyword arguments. The method used `kw_args.update(self._bound_variables)` which overwrites per-call kwargs with bound variables. For example, after `logger.bind(project="default")`, calling `logger.info("msg", project="specific")` would log `project="default"` instead of the caller's `project="specific"`. Fixed by constructing the merged dict with bound variables as the base and per-call kwargs as overrides: `kw_args = {**self._bound_variables, **kw_args}`.

- **[DB]** Fix `HTTPRunDB.store_artifact` silently omitting the `iter` query parameter when `iter=0`. The method used a falsy check (`if iter:`) to decide whether to include the iteration in the API request params. Since `0` is falsy in Python, passing `iter=0` (the root iteration) would skip adding the parameter entirely, causing the artifact to be stored without its iteration context. The sister method `read_artifact` correctly used `if iter is not None:`. Fixed by using `is not None` check consistent with the rest of the codebase.

- **[Alerts]** Fix `AlertConfig.to_dict` silently discarding `exclude` and `strip` parameters. The overridden `to_dict` method accepted `exclude` and `strip` keyword arguments but only forwarded the `fields` argument to the parent `ModelObj.to_dict`, ignoring the caller's `exclude` and `strip` values. This meant calling `alert.to_dict(exclude=["project"])` would still include the `project` field in the output, and `strip=True` would have no effect. Fixed by forwarding `exclude` and `strip` to the parent call.

- **[Nuclio]** Fix `_validate_triggers` overwriting `explicit_ack_enabled` flag on each loop iteration instead of accumulating it. The validation loop checks whether any trigger has explicit acknowledgment enabled, but the boolean variable was reassigned (not OR'd) on each iteration, so only the last trigger's setting was retained. If an earlier trigger had `explicitAckMode` enabled but the last trigger did not, the validation would incorrectly pass, allowing multiple triggers with explicit ack -- a configuration unsupported on older Nuclio versions. Fixed by using `or` to accumulate the flag across all triggers.

- **[Regex]** Fix `dns_1035_label` regex pattern missing `^` and `$` anchors, allowing invalid Spark job names to pass validation. The pattern `[a-z]([-a-z0-9]*[a-z0-9])?` is used via `re.match` which only checks from the start of the string without requiring the pattern to span the entire input. Without a `$` anchor, names with invalid trailing characters (e.g., `"valid123!!!"`) would match because `re.match` successfully matches the valid prefix and ignores the rest. This allowed Spark job names violating DNS 1035 (which requires only lowercase alphanumeric and hyphens) to pass the service-name validation check. Fixed by adding `^` and `$` anchors to enforce full-string matching.

- **[Utils]** Fix `fill_object_hash` not restoring `metadata.updated` after computing hash. The function temporarily clears `tag`, `status`, `updated`, and `created` from the dict before hashing, but only restores `tag`, `status`, and `created` afterwards — the `updated` timestamp is set to `None` and never restored. This silently wipes out the `updated` field on any artifact or function dict passed through this function. The analogous object-based function `calc_hash` in `runtimes/utils.py` correctly saves and restores `updated`. Fixed by using `pop` to save the original `updated` value and restoring it after hash computation.

- **[Runs]** Fix `delete_runs` indexing the wrong list when handling chunk failures. In the chunked batch deletion loop, failed results were looked up via `runs_list[i]` (the full list) instead of `chunked_run_list[i]` (the current chunk). For the second and subsequent chunks, `i` is an offset within the chunk but was used against the full list, causing the wrong run UID to be removed from the deletion set and the wrong run details to be logged in the warning message. Fixed by indexing into `chunked_run_list` instead of `runs_list`.

- **[Errors]** Fix `STATUS_ERRORS` lookup table missing entries for `HTTPStatus.GATEWAY_TIMEOUT` (504) and `HTTPStatus.METHOD_NOT_ALLOWED` (405). The `raise_for_status` helper uses this table to map HTTP status codes to specific `MLRun` exception classes. Because `504` and `405` were not in the table, server responses with these status codes raised the generic `MLRunHTTPError` instead of the specific `MLRunTimeoutError` or `MLRunMethodNotAllowedError`. This meant any code catching `MLRunTimeoutError` to handle gateway timeouts (e.g., retry logic) would miss the exception entirely. Fixed by adding both missing mappings to the `STATUS_ERRORS` dictionary.

- **[Execution]** Fix `MLClientCtx.get_notifications` always returning empty list when `unmask_secret_params=False`. The `notifications.append(notification)` call was nested inside the `if unmask_secret_params:` block, so when called with the default `unmask_secret_params=False`, the loop iterated over all notifications but never added any to the result list. Fixed by moving the `append` call outside the conditional block, so notifications are always collected, and only the secret enrichment step is conditional on `unmask_secret_params`.

- **[Data Types]** Fix `python_type_to_value_type` mapping `int8` and `uint8` Python types to `ValueType.INT32` instead of their correct `ValueType.INT8` and `ValueType.UINT8`. This caused the feature store to record these narrow integer types as `int32`, losing the original type information and preventing proper range validation (e.g., the INT8 range validator of -128 to 127 would never be applied). Fixed by mapping `int8` to `ValueType.INT8` and `uint8` to `ValueType.UINT8`.

- **[K8s Utils]** Fix `_prune_node_selector` discarding user node selectors when preemptible node selector config is empty. When preemption is configured via tolerations only (no node selector), `_prune_node_selector` receives an empty `node_selector` dict to prune, triggers the `not node_selector` early-return guard, and returns `None` instead of the original `enriched_node_selector`. The caller assigns this `None` back, silently wiping out all user-defined node selectors. Fixed by returning `enriched_node_selector` from the early-return path so that user selectors are preserved when there is nothing to prune.

- **[Features]** Fix `RangeTypeValidator.check` crashing with `TypeError` when reporting out-of-range values. The method passed the raw numeric `value` to `_limited_string()`, which expects a string argument and calls `len(value)` internally. For numeric types (INT8, INT16, INT32, etc.), this raises `TypeError: object of type 'int' has no len()`, masking the actual validation error. Fixed by wrapping `value` in `str()` before passing to `_limited_string()`, consistent with how `MinMaxValidator.check` already handles it.

- **[Scheduler]** Fix `ScheduleCronTrigger.to_crontab` producing invalid crontab strings with literal `"None"` for unset fields. When a `ScheduleCronTrigger` was constructed directly (not via `from_crontab`) with some fields left as `None`, `to_crontab()` used Python f-string interpolation which rendered `None` as the string `"None"` (e.g., `"0 9 None None None"` instead of `"0 9 * * *"`). The resulting string is not a valid crontab expression and cannot be parsed back. Fixed by coalescing `None` fields to `"*"` (the standard crontab wildcard) during serialization.

- **[K8s Utils]** Fix `sanitize_label_value` producing invalid K8s label values that start or end with non-alphanumeric characters. The function used a single-pass `re.sub` with `^` and `$` anchors to replace non-alphanumeric start/end characters with `-`, but since `re.sub` only matches anchors against the original input, the replacement character `-` itself could end up at the start or end of the result, violating the K8s label constraint that values must begin and end with an alphanumeric character. For example, `.hello.` became `-hello-` (invalid) instead of `hello` (valid). Fixed by replacing all invalid middle characters first, then stripping non-alphanumeric characters (`_`, `.`, `-`) from both ends.

- **[Features]** Fix UINT128 range validator using `2^128` instead of `2^128 - 1` as the upper bound. The `RangeTypeValidator` for `ValueType.UINT128` accepted the value `2^128` as valid, which exceeds the maximum representable value for a 128-bit unsigned integer (`2^128 - 1`). This is inconsistent with the INT128 validator, which correctly uses `2^127 - 1`. Fixed by subtracting 1 from the upper bound.

- **[Builder]** Fix `_validate_and_merge_args_with_extra_args` always reading the value of the first `--build-arg` when building the existing build-arg dict. The dict comprehension used `args.index(arg)` to find the position of each `--build-arg` flag, but `list.index()` always returns the index of the first occurrence. With multiple `--build-arg` flags (e.g., `["--build-arg", "A=1", "--build-arg", "B=2"]`), every iteration resolved to the first `--build-arg` at index 0, reading `"A=1"` each time and never seeing `"B=2"`. This caused duplicate build-arg values to be silently added or valid new build-args to overwrite existing ones without error. Fixed by using `enumerate()` to track the actual index of each `--build-arg` flag.

- **[Scheduler]** Fix `_ensure_auth_info_has_access_key` using `lstrip()` instead of `removeprefix()` to strip the `$ref:` secret reference prefix from an access key. `lstrip("$ref:")` strips individual characters from the set `{$, r, e, f, :}` rather than removing the prefix as a substring. If the secret name after `$ref:` begins with any of those characters (e.g., `$ref:ref-secret` would become `secret` instead of `ref-secret`), the wrong secret name is resolved, leading to a failed or wrong secret lookup. Fixed by using `removeprefix()` which correctly removes only the exact prefix string.

- **[API]** Fix `abort_run` endpoint using `in` (substring check) instead of `==` (equality) when comparing background task state to `BackgroundTaskState.running`. Since `BackgroundTaskState.running` is a `StrEnum` with value `"running"`, the `in` operator performs a substring match against the string rather than an equality comparison. While this happens to work for the exact state values in practice, it is a logic error (any substring of `"running"` such as `"run"` or `"n"` would also match). Fixed by changing `in` to `==`, consistent with the `== BackgroundTaskState.succeeded` check on the next branch.

- **[Artifacts]** Fix `ModelArtifactSpec.__init__` parameter typo `paraemeters` instead of `parameters`. The misspelled constructor parameter meant that calling `ModelArtifactSpec(parameters={"lr": 0.01})` would raise a `TypeError` (unexpected keyword argument), and any code passing parameters via the constructor would silently get an empty dict instead. Fixed by renaming the parameter to `parameters`.

- **[Pipelines]** Fix `create_pipeline` rejecting zip content type due to spurious space in substring check. The condition `" /zip" in content_type` (with a leading space before `/zip`) never matched standard MIME types like `"application/zip"`, causing all zip pipeline submissions to be rejected with `"unsupported pipeline type"`. Fixed by removing the spurious space: `"/zip" in content_type`.

- **[Runtimes]** Fix `_build_watch` not showing full build log on failure when `show_on_failure=True`. The method advanced the log offset after the initial read but suppressed printing (since the build hadn't failed yet). When the build later failed and the log was "re-read", it used the accumulated offset instead of starting from 0, causing the initial portion of the build log to be permanently lost. Fixed by resetting `offset` and `events_offset` to 0 when re-reading on failure.

- **[Model]** Fix `RunObject._artifact` and `_process_artifacts` using `datetime.min` as default sort key for missing `created` metadata. The `created` field in artifact metadata is stored as an ISO-format string. When some artifacts have `created` and others do not, the sort mixes string values with `datetime.min` (a `datetime` object), raising `TypeError: '<' not supported between instances of 'str' and 'datetime.datetime'`. Fixed by using an empty string `""` as the default, which sorts before any ISO date string and maintains the intended "missing dates first" ordering.

- **[Projects]** Fix `_calculate_pipelines_counters` using `in` operator to compare pipeline status against `RunStatuses.succeeded` (a string). The check `pipeline["status"] in mlrun.run.RunStatuses.succeeded` performs a substring check against the string `"Succeeded"` instead of an equality comparison. While this happens to work for the exact status string `"Succeeded"`, it would incorrectly match any substring (e.g., `"S"`, `"ceed"`). Fixed by changing `in` to `==` for a proper equality comparison, consistent with the `_failed_statuses()` list-membership check on the next line.

- **[Runtimes]** Fix `DatabricksRuntime.run` silently dropping the `retry` parameter. The method accepted `retry` as a keyword argument but did not pass it through to `super().run()`, causing any retry configuration (count, backoff strategy) to be ignored for Databricks jobs. Fixed by adding `retry=retry` to the `super().run()` call.

- **[Runtimes]** Fix Spark3 runtime handler `_enrich_resources` raising `KeyError` when executor or driver resources have `requests` but no `limits`. The GPU extraction code accessed `resources["limits"]` unconditionally inside the `if "requests" in resources:` block, crashing when only CPU/memory requests were set without any limits. Fixed by guarding the GPU extraction with `if "limits" in resources:` checks for both executor and driver.

- **[Execution]** Fix `MLClientCtx.get_param` not persisting falsy default values to the run DB. The check `if default:` treated `0`, `False`, `""`, and `[]` as "no default", skipping the `_update_run()` call that persists the parameter to the DB. Changed to `if default is not None:` so that only `None` is treated as "no default to persist".
- **[Utils]** Fix `_split_by_dots_with_escaping` not resetting the escape flag after consuming an escaped character. After a backslash-dot sequence (`\.`), the `escape` flag remained `True` for all subsequent characters, causing every later dot to also be treated as a literal character instead of a key separator. For example, `update_in(obj, r"a\.b.c", val)` would treat the entire `a.b.c` as a single key instead of correctly splitting into `["a.b", "c"]`. Fixed by resetting `escape = False` in the else branch after appending the character.
- **[Runtimes]** Fix `MPIJobV1Alpha1States.mpijob_state_to_run_state` raising `KeyError` when an MPI job transitions to the `Failed` state. The lookup dict incorrectly used `SparkApplicationStates.failed` (`"FAILED"`) as the key instead of `MPIJobV1Alpha1States.failed` (`"Failed"`), causing every MPI job failure to surface as an unhandled `KeyError` rather than mapping to `RunStates.error`.
- **[Alerts]** Fix `_validate_alert_criteria` using `>=` instead of `>` when comparing `criteria.count` against `max_criteria_count`. This caused a criteria count equal to the configured maximum (default: 100) to be incorrectly rejected with "Maximum criteria count exceeded", making the effective upper bound one less than the configured limit. Changed to `>` so that `criteria.count == max_criteria_count` is accepted as a valid value.

- **[API]** Fix `_ensure_function_has_auth_set` using `lstrip()` instead of `removeprefix()` to strip the `$ref:` secret reference prefix from a function's access key. `lstrip("$ref:")` strips individual characters from the set `{$, r, e, f, :}` rather than removing the prefix as a substring. If the secret name after `$ref:` begins with any of those characters (e.g., `$ref:ref-secret` would become `secret` instead of `ref-secret`), the wrong secret name is resolved, leading to a failed or wrong secret lookup when setting auth env vars. Fixed by using `removeprefix()` which correctly removes only the exact prefix string.
- **[Utils]** Fix `AsyncRetryer._perform_call` silently swallowing exceptions when `backoff >= timeout`. The method was missing `self.last_exception = exc` before constructing the return tuple. Because Python evaluates tuple elements left-to-right, `self.last_exception` (element 1) was read as `None` before `_assert_failure_timeout` (element 2) had a chance to assign it. When the backoff interval equalled or exceeded the remaining timeout, `_assert_failure_timeout` returned `False` (don't retry), and the caller's `exc` variable was `None`, causing the `elif not exc: return result` branch to return `None` instead of raising `MLRunRetryExhaustedError`. The fix adds the missing assignment so the current exception is captured before the tuple is built.
- **[Operations]** Fix `_store_mail_notifications_default_params_to_secret` catching wrong exception type. The function imported `ApiException` from `kfp_server_api` (KFP pipeline API) but used it to catch errors from `k8s_helper.store_secrets()`, which raises `kubernetes.client.rest.ApiException`. Since these are different exception classes, any Kubernetes API error during secret storage would go uncaught and propagate as an unhandled exception instead of being logged as a warning. Fixed by importing `ApiException` from `kubernetes.client.rest` instead.
- **[Utils]** Fix `clone_git` using `str.replace()` instead of `str.removeprefix()` for stripping Git ref prefixes. `replace("refs/heads/", "")` removes all occurrences of the substring, not just the prefix. If a branch name contains the prefix string (e.g., `refs/heads/fix-refs/heads/issue`), the embedded occurrence is also removed, producing `fix-issue` instead of the correct `fix-refs/heads/issue`. The same bug affects `refs/tags/` and `refs/commits/` parsing. Fixed by using `removeprefix()` which only removes the exact prefix.
- **[Runtimes]** Fix `get_resource_labels` using `split("@")` without `maxsplit` to extract owner username and domain. If `run_owner` contains more than one `@` character, `split("@")` produces more than two elements and the tuple unpacking `run_owner, domain = run_owner.split("@")` raises `ValueError: too many values to unpack`. Fixed by using `split("@", 1)` to limit the split to one occurrence, keeping any extra `@` characters in the domain part.
- **[API]** Fix `_get_files` using `str.split()` instead of `os.path.split()` to extract the filename from the object path. The call `objpath.split(objpath)` splits the string by itself as delimiter, always producing `["", ""]`, so `filename` is always an empty string. This causes the `x-suggested-filename` response header to always be empty, preventing clients from knowing the original filename when downloading files. Fixed by using `os.path.split(objpath)` which correctly splits a path into `(directory, filename)`.

- **[API]** Fix `delete_runs` silently skipping DB deletion and log cleanup for batch deletes. The method used `run_function_with_new_db_session` (a synchronous helper) to invoke `self._delete_runs` (an `async def`). The sync helper called the function without `await`, immediately receiving an unawaited coroutine object that was returned before the sync session context-manager closed. When `asyncio.gather` later attempted to run the coroutine, the DB session was already closed — so neither `del_runs` nor the log-collector cleanup ever executed. Fixed by switching to `run_async_function_with_new_db_session`, which detects coroutine functions and awaits them with a proper async-compatible DB session.
- **[Runtimes]** Fix `RunStates.run_state_to_pipeline_run_status` raising `KeyError` for `pending_retry` state. The state-to-pipeline-status mapping dict was missing the `pending_retry` entry, causing a `KeyError` when a run in `pending_retry` state was mapped to a pipeline run status (e.g., during local pipeline execution in `_LocalRunner`). Added the missing mapping to `RunStatuses.failed` since `pending_retry` is classified as an error state.

- **[Events]** Fix `_generate_auth_secret_event` always emitting a "created" event kind regardless of the actual action. The method hardcoded `kind=PROJECT_AUTH_SECRET_CREATED` instead of selecting between `PROJECT_AUTH_SECRET_CREATED` and `PROJECT_AUTH_SECRET_UPDATED` based on the `action` parameter. This caused auth secret update events to be incorrectly reported as creation events. Fixed by mapping the action to the corresponding event kind constant.
- **[Runtimes]** Fix `SparkApplicationStates.spark_application_state_to_run_state` mapping `SUBMISSION_FAILED` to `RunStates.running` instead of `RunStates.error`. When a Spark application fails to submit to the cluster, the run was incorrectly reported as still running, preventing error handling and leaving the run stuck in a non-terminal running state indefinitely.
- **[API]** Fix `_delete_run_resources` missing early return after grace period check. The method logs "Skipping deleting runtime resources" when a run's start time exceeds the deletion grace period, but never actually returns — falling through to delete the runtime resources anyway. This defeats the grace period optimization, causing unnecessary Kubernetes API calls for old runs whose resources have already been cleaned up.
- **[Monitoring]** Fix `_list_runs_for_monitoring` overwriting `duplicated_runs` list with a dict on each duplicate, losing all previously detected duplicates and always logging `None` metadata. The code used `duplicated_runs = {...}` (dict assignment) instead of `duplicated_runs.append({...})` (list append), and accessed metadata via `.get(["metadata"])` (passing a list as a dict key, which never matches any key) instead of `.get("metadata")`.
- **[Pipelines]** Fix `_KFPRunner.run` mutating `notification.params` in-place when merging secret params. The code used `params = notification.params` followed by `params.update(notification.secret_params)`, which modified the original notification object's `params` dict by injecting the secret param values into it. This caused the mutated params (now containing secret values) to be passed to `add_notification` alongside the separate `secret_params`, resulting in secret params being stored in both fields. Fixed by constructing a new merged dict instead of mutating the original.
- **[Model]** Fix `ImageBuilder.with_requirements` ignoring the `overwrite` flag due to operator precedence. The expression `self.requirements or [] if not overwrite else []` was parsed by Python as `self.requirements or ([] if not overwrite else [])`, which always evaluates to `self.requirements or []` regardless of `overwrite`. When `overwrite=True`, the method should start with an empty list but instead always kept the existing requirements, silently appending new ones rather than replacing them.
- **[Notifications]** Fix `WebhookNotification.push` mutating the `override_body` template in `self.params` in-place. When `override_body` contained `{{ runs }}` placeholders, `_serialize_runs_in_request_body` replaced them directly in the stored dict. On subsequent calls to `push()`, the `{{ runs }}` template was already consumed, so the new run data was never substituted — the notification permanently contained stale data from the first push. Fixed by deep-copying `override_body` before performing the substitution.
- **[Notifications]** Fix `SlackNotification._get_run_line` operator precedence bug causing broken Slack links. The condition `url and not kind or kind == "run"` was parsed as `(url and not kind) or (kind == "run")` due to Python's operator precedence rules. When `step_kind` was `"run"` but `url` was `None` (e.g., no UI configured), the condition evaluated to `True`, producing a broken Slack hyperlink `<None|*name*>`. Fixed by adding parentheses: `url and (not kind or kind == "run")`.
- **[API]** Fix `ServerSideLauncher._configure_serving_spec` using dict-style indexing on `function.spec.env` (a list) to set `SERVING_SPEC_ENV`. The code `function.spec.env["SERVING_SPEC_ENV"] = serving_spec` raises a `TypeError` because `spec.env` is a list of `V1EnvVar` objects, not a dict. This breaks server-side execution of any `KubejobRuntime` or `RemoteRuntime` with a serving spec smaller than the configmap cutoff. Fixed by using `function.set_env("SERVING_SPEC_ENV", serving_spec)`.
- **[Runtimes]** Fix `_enrich_and_validate_v3io_mounts` using `and` instead of `or` in the volume mounts type validation. The condition `not isinstance(volume_mounts, list) and any(...)` short-circuits when `volume_mounts` IS a list (the normal case), causing the element type check to never execute. This means a list containing non-`VolumeMount` objects (e.g., plain dicts or strings) is silently accepted instead of raising `TypeError`. Fixed by changing `and` to `or` so that the validation correctly rejects both non-list inputs and lists with invalid element types.
- **[Runtimes]** Fix `APIGateway._resolve_canary` using truthiness check on the final canary assignment. The check `if percentage_1 and percentage_2` fails when either computed percentage is 0 (a valid value representing 0% traffic), causing `canary` to remain `[0, 0]` instead of the correct values (e.g., `[100, 0]`). This occurs during round-trip conversion of an API gateway with canary set to `[100, 0]`: the `to_scheme()` method only sets the first upstream's percentage, and the second defaults to 0. When `_resolve_canary` correctly computes `percentage_2 = 0`, the truthiness check rejects it. Fixed by using `is not None` for the final canary assignment check.
- **[Runtimes]** Fix `exec_from_params` silently dropping falsy handler return values. The check `if val:` treated return values such as `0`, `0.0`, `False`, `""`, `[]`, and `{}` as "no return value", causing them not to be logged as results. Changed to `if val is not None:` so that only `None` (the default when no return statement is used) is excluded. This means handlers returning zero, an empty string, or other legitimate falsy values now correctly have those values logged as the `"return"` result.
- **[Runtimes]** Fix `calc_hash` not restoring `metadata.updated` after computing the function hash. The function temporarily clears `tag`, `hash`, `status`, and `updated` to get a stable hash, but only restores the first three. After any call to `calc_hash` (e.g., during `export()` or `save()`), the function object's `updated` timestamp is silently set to `None`, losing the original value.
- **[Projects]** Fix `_resolve_existing_artifact` calling `from_dict` on an Artifact object instead of returning it directly. When an existing artifact was found, the method called `existing_artifact.from_dict(existing_artifact)`, passing an Artifact object where a dict was expected. This raises a `TypeError` because `ModelObj.from_dict` uses `if field in struct` to iterate over the struct, and `Artifact` does not support `__contains__`. Fixed by returning `existing_artifact` directly, since `get_artifact` already returns a proper Artifact object.
- **[API]** Fix `_get_artifacts_from_uris` overwriting the `project` parameter inside the loop. The tuple unpacking `project, key, ... = parse_artifact_uri(uri, project)` reassigned the function's `project` parameter on each iteration. If the first artifact URI contained a different project name, subsequent URIs would be parsed with the wrong default project. More critically, the final `list_artifacts_for_producer_id` call used the overwritten `project` value (from the last URI) instead of the original function parameter. Fixed by unpacking into `artifact_project` instead of shadowing `project`.
- **[Projects]** Fix `_resolve_artifact_producer` calling `.get()` on an `ArtifactProducer` object instead of the extracted dict. When the artifact's producer is an `ArtifactProducer` instance (not a dict) and the `get_meta()` dict lacks a `project` key (which it always does), the fallback URI resolution path used `artifact.spec.producer.get("uri", "")` on the `ArtifactProducer` object, which does not have a `.get()` method. This raises `AttributeError` when re-logging an artifact whose producer is an `ArtifactProducer` with a missing or empty tag/project. Fixed by using `producer_dict.get("uri", "")` which correctly operates on the plain dict extracted from `get_meta()`.
- **[Launcher]** Fix `_enrich_run` ignoring explicit `verbose=False` due to falsy-value bug. The expression `verbose or run.spec.verbose` treats `False` the same as `None` (not provided), so passing `verbose=False` to disable verbosity on a run that already has `verbose=True` has no effect -- the run stays verbose. Fixed by using `verbose if verbose is not None else run.spec.verbose` to properly distinguish between "not provided" (`None`) and "explicitly disabled" (`False`).
- **[Config]** Fix `Config.use_nuclio_mock` returning `None` instead of `False` when mock is disabled and no explicit `force_mock` is provided. The ternary expression `True if mock_nuclio and force_mock is None else force_mock` short-circuits to `force_mock` (which is `None`) when `mock_nuclio` is falsy, instead of returning `False`. This causes callers checking the result with `is False` or `is True` to get unexpected behavior. Fixed by separating the force_mock check from the config evaluation so the method always returns a proper boolean.
- **[Logs]** Fix `Logs.delete_run_logs_legacy` using `shutil.rmtree()` (directory removal) to delete a run log file. The `log_path()` helper returns a file path (not a directory), since `store_log()` creates logs as regular files via `open()`. Calling `shutil.rmtree()` on a regular file raises `NotADirectoryError`, causing the legacy log deletion fallback to fail. Fixed by replacing `shutil.rmtree()` with `Path.unlink()`.
- **[API]** Fix `DatastoreProfiles._delete_secret` passing a `SecretsData` object as the `provider` argument to `delete_project_secret` and omitting the `secret_key` argument entirely. The method constructed `SecretsData(provider=..., secret_key=...)` and passed it as the second positional argument, but `delete_project_secret` expects `provider` (a `SecretProviderName` enum) as the second argument and `secret_key` (a string) as the third. This caused the deletion call to fail with a type mismatch. Fixed by passing the provider and secret key as separate arguments.
- **[DB]** Fix `HTTPRunDB.get_log` not passing `attempt` parameter to `watch_log` when `size=-1`. When retrieving all logs (`size=-1`) for a specific retry attempt, the `attempt` argument was silently dropped in the delegation to `watch_log`, causing logs from the wrong attempt (the latest) to be returned instead of the requested one. Fixed by forwarding the `attempt` parameter.
- **[Secrets]** Fix `InMemorySecretProvider.list_user_token_secrets` raising `KeyError` when `secrets_map` contains non-token secrets, and missing `user_id` in `SecretTokenInfo` construction. The method iterates over all entries in `secrets_map` and accesses `["user_id"]` unconditionally, but `store_secret()` stores arbitrary dicts that may not contain this key. Additionally, the `SecretTokenInfo` constructor was missing the required `user_id` field. Changed the filter condition to use `.get("user_id")` so non-token secrets are safely skipped, and added the missing `user_id` parameter to the `SecretTokenInfo` constructor.
- **[API]** Fix `Notifications.delete_run_notifications` not cleaning up notification param secrets when deleting all notifications for a run. When called without a `name` (to delete all notifications), the filter `notification.name == name` compared against `None`, matching no notifications since all have actual names. This left orphaned secrets in the project secret store. Also fixed the single-notification case which only processed the first match and skipped any remaining. Changed to match all notifications when `name is None` and iterate over all matches for secret cleanup.
- **[Runtimes]** Fix `Spark3Runtime.with_dynamic_allocation` ignoring zero values for `min_executors`, `max_executors`, and `initial_executors`. The method used truthiness checks (`if min_executors:`) instead of `is not None` checks, causing `0` to be treated as "not provided". This meant setting `min_executors=0` (a valid Spark dynamic allocation configuration) had no effect. Fixed by changing all three checks to `is not None`.
- **[Pipelines]** Fix `_filter_runs_by_name` missing early return when `target_name` is empty, causing every run to be yielded twice. When called with an empty `target_name` and a re-iterable `runs` input (e.g., a list), the generator first yields all runs unfiltered, then falls through to the filtering loop where `"" in run_name` is always `True`, yielding all runs a second time. Fixed by adding `return` after the unfiltered yield loop.
- **[Auth]** Fix `resolve_jwt_subject` catching wrong exception type `jwt.PyJWTError` instead of `mlrun.errors.MLRunInvalidArgumentError`. The internal `_decode_token_unverified` function wraps JWT decode errors in `MLRunInvalidArgumentError`, which does not inherit from `jwt.PyJWTError`. This means the except block in `resolve_jwt_subject` never catches decode failures, causing them to propagate as unhandled exceptions instead of being gracefully handled with `raise_or_log_error`. The sibling function `resolve_jwt_username` correctly catches `MLRunInvalidArgumentError`.
- **[Model]** Fix `RunSpec.tolerations` defaulting to an empty dict `{}` instead of an empty list `[]`. Tolerations are a list of Kubernetes V1Toleration objects, but the default value was `{}` (empty dict). This caused wrong type behavior when code appended to `run.spec.tolerations` or when the value was serialized — a dict where a list is expected. Fixed by changing the default from `{}` to `[]`.
- **[Runtimes]** Fix `RemoteRuntime._get_state` reversed boolean condition suppressing exceptions when it should raise, and raising when it should suppress. The `raise_on_exception` parameter had its logic inverted: when `True` (should raise), the method silently returned empty values; when `False` (should suppress), it raised a `ValueError`. Fixed by changing `if raise_on_exception` to `if not raise_on_exception`.
- **[Artifacts]** Fix `ArtifactManager.log_artifact` failing to detect HTML files by extension. The suffix comparison `pathlib.Path(src_path).suffix == "html"` never matches because `pathlib.Path.suffix` returns the extension with the leading dot (`.html`), not without it. This means the `viewer` is never set to `"web-app"` based on file extension, only when `format="html"` is explicitly passed. Fixed by comparing against `".html"` instead of `"html"`.
- **[Pipelines]** Fix `delete_pipelines_runs` logging wrong identifiers on failure due to stale loop variables. The `concurrent.futures.as_completed` loops used `pipeline_run.id` and `experiment_id` from the outer submission loops, which always held the last value rather than the identifier of the actually failed future. Fixed by mapping each future to its corresponding run/experiment ID via a dictionary.
- **[Runtimes]** Fix `Spark3Runtime` `driver_affinity` setter passing `"executor_affinity"` as the attribute name to `transform_attribute_to_k8s_class_instance` instead of `"driver_affinity"`. This is a copy-paste error from the `executor_affinity` setter. When validation fails on a driver affinity value, the error message incorrectly reports the problem as being with `executor_affinity`, misleading users about which attribute has the issue.
- **[Runtimes]** Fix `ast_code` in `funcdoc.py` crashing with `AttributeError` when parsing function defaults that are method calls (e.g., `datetime.now()`, `os.path.join("a", "b")`). The code assumed `expr.func` is always an `ast.Name` node with an `.id` attribute, but for attribute-based calls like `module.func()`, `expr.func` is an `ast.Attribute` node which has no `.id`. This caused `find_handlers` and `update_function_entry_points` to fail when processing any function with a method-call default parameter. Fixed by using `ast.unparse(expr.func)` which correctly handles both simple names and dotted attribute paths.
- **[Runtimes]** Fix `run_exec` ignoring custom environment variables passed by the caller. The function receives an `env` dict with overrides like `PYTHONPATH` and `MLRUN_LOG_LEVEL` but passes `os.environ` directly to `Popen`, silently discarding the overrides. This means local subprocess runs without a handler never see the configured `PYTHONPATH` or verbose log level. Fixed by merging the custom `env` dict into a copy of `os.environ` before passing it to `Popen`.
- **[Workflows]** Fix `_update_dict` in workflow submission endpoint silently dropping falsy values like `False`, `0`, and `""` when merging workflow spec overrides. The condition `elif val:` was used instead of `elif val is not None:`, causing legitimate falsy values to be treated as unset. For example, setting `run_local=False` or `ttl=0` in a workflow request would be silently ignored if the project's existing workflow had different values.
- **[Utils]** Fix `Retryer` and `AsyncRetryer` backoff never progressing past the first interval. The `first_interval` field was never reset to `None` after the first loop iteration, so `self.first_interval or next(self.backoff)` always short-circuited to `self.first_interval`, making every retry sleep for the same initial interval regardless of the configured backoff strategy. Additionally, `AsyncRetryer.run()` was missing the `type(exc) not in self.fatal_exceptions` guard, causing it to always retry even on exceptions explicitly marked as fatal instead of propagating them immediately.
- **[API]** Fix `store_api_gateway` comparing `get_invoke_url` method objects instead of their return values. The condition `existing_api_gateway.get_invoke_url != api_gateway.get_invoke_url` compared bound method references (which are always unequal for different objects) instead of calling them with `()`. This caused every API gateway update to unnecessarily delete invocation URLs from all associated functions, even when the URL had not changed, and made the `elif unused_functions` branch unreachable.
